# เครื่องมือตั้งค่าเซนเซอร์ RS485 (ใช้กับของจริง ไม่มีค่าจำลอง)

2 sketch แยกจากโปรเจกต์หลัก ใช้ **Arduino Nano ตัวเดียวกัน + MAX485 ตัวเดิม** ไม่ต้องต่อจอ

| Sketch | ใช้ทำอะไร | ทำเมื่อไหร่ |
|---|---|---|
| [`RS485_SetID/`](RS485_SetID/) | หา + **ตั้ง Slave ID** ของเซนเซอร์ และไล่หา register | **ทำก่อน** |
| [`RS485_ReadAll/`](RS485_ReadAll/) | อ่านเซนเซอร์ **3 ตัวพร้อมกัน** บนบัสเดียว | ทำหลังตั้ง ID ครบ |

> **หมายเหตุศัพท์:** Modbus RTU ไม่มี "IP address" — สิ่งที่ต้องตั้งเรียกว่า **Slave ID / Device Address** (เลข 1-247)

---

## ทำไมต้องตั้ง ID ก่อน

เซนเซอร์จีนเกือบทั้งหมด**มาจากโรงงานด้วย ID = 1 เหมือนกันหมด**
ถ้าเอา O2 สองตัวไปต่อบัสเดียวกันเลย มันจะ**ตอบพร้อมกันแล้วชนกันบนสาย** → อ่านไม่ได้สักตัว และหาสาเหตุยากมาก

⚠️ **ตอนตั้ง ID ต้องต่อเซนเซอร์ทีละตัวเท่านั้น**

---

## การต่อสาย (เหมือนโปรเจกต์หลัก ไม่ต้องรื้อ)

```
Nano D2  ──> MAX485 DE + RE (ต่อเข้าด้วยกัน)
Nano D8  <── MAX485 RO       (AltSoftSerial RX — ขาตายตัว)
Nano D9  ──> MAX485 DI       (AltSoftSerial TX — ขาตายตัว)
MAX485 VCC ── 5V     GND ── GND
MAX485 A/B ──> เซนเซอร์ A/B
```

**D0/D1 ว่าง** → ใช้คุยกับ Serial Monitor ได้เลย
(นี่คือผลพลอยได้จากที่โปรเจกต์นี้เลือก `AltSoftSerial` ตั้งแต่แรก — ถ้าใช้ `SoftwareSerial` มันจะปิด interrupt จน Serial Monitor เพี้ยน)

**GND ของเซนเซอร์ต้องถึง GND ของ Nano เสมอ** ไม่งั้น RS485 จะรวน

---

## ขั้นตอนที่ 1 — ตั้ง Slave ID

อัปโหลด `RS485_SetID/RS485_SetID.ino` → เปิด **Serial Monitor ที่ 115200** และตั้ง **Newline**

### 1. ต่อ O2 ตัวแรก (ตัวเดียว) แล้วหาว่ามันคือ ID อะไร

```
> scan
```
กวาด ID 1-247 ใช้เวลา ~20 วินาที (ใช้ timeout 80 ms จึงเร็ว)

ถ้าไม่เจอ ลอง:
```
> scanall
```
กวาดทุก baud (9600 / 4800 / 19200 / 38400)

**ยังไม่เจออีก?** → เช็ค: สาย **A กับ B สลับกัน**ไหม · เซนเซอร์**มีไฟเลี้ยง**ไหม · **GND ถึงกัน**ไหม

### 2. หา register ที่เก็บ "ที่อยู่ของตัวเอง"

```
> probe 1
```
เครื่องมือจะไล่อ่าน register ที่ผู้ผลิตนิยมใช้ แล้ว**มาร์กตัวที่มีค่าเท่ากับ ID ปัจจุบัน** ให้

```
  reg      hex     value    หมายเหตุ
  2000     0x7D0   1        <<< น่าจะเป็น ADDRESS ตัวนี้ (ค่าตรงกับ ID)
  2001     0x7D1   3
```
→ register **2000** คือตัวที่ต้องเขียนเพื่อเปลี่ยน ID

ถ้า probe ไม่เจอ ให้ไล่ดูเองด้วย:
```
> regs 1 0 20        (ดู register 0-19)
> regs 1 2000 10     (ดู register 2000-2009)
```

### 3. ตั้ง ID

```
> setid 1 2000 1     ← O2 ตัวแรก  = ID 1
```
เครื่องมือจะ **อ่านค่าเดิมก่อน** (ถ้าอ่านไม่ได้จะไม่ยอมเขียน — กันเขียนมั่วลง register ผิด) แล้วเขียน แล้ว **ยืนยันผลให้**

### 4. ทำซ้ำกับตัวที่เหลือ (ต่อทีละตัว!)

```
ถอด O2 ตัวแรก → ต่อ O2 ตัวที่สอง
> scan               (จะเจอ ID 1 อีก เพราะโรงงานตั้งมาเหมือนกัน)
> setid 1 2000 2     ← O2 ตัวที่สอง = ID 2

ถอด → ต่อ Pressure
> scan
> setid 1 2000 3     ← Pressure = ID 3
```

> ถ้าหลัง setid แล้วยืนยันไม่ผ่าน → **ปิด-เปิดไฟเซนเซอร์** แล้ว `scan` ใหม่
> (บางรุ่นต้อง power cycle ก่อน ID ใหม่ถึงจะมีผล)

### 5. ต่อทั้ง 3 ตัวเข้าบัสเดียวกัน แล้วตรวจ

```
> scan
```
**ต้องเจอครบ 1, 2, 3** ถ้าเจอไม่ครบ = ยังมี ID ซ้ำ หรือสายหลุด

### 6. หา register ของ "ค่าที่วัดได้" (ยังต้องใช้ต่อ)

```
> regs 1 0 30
```
เครื่องมือจะ **มาร์กค่าที่คำนวณแล้วได้ ~20.9 ให้อัตโนมัติ** — เพราะ **O2 ในอากาศปกติ = 20.9 %**

```
  reg      hex     u16      x0.1     x0.01
  0        0x0     209      20.9     2.09     <<< x0.1 ได้ ~20.9 = น่าจะเป็นค่า O2!
```
→ O2 อยู่ที่ register **0**, function **03**, scale **0.1**

ถ้า FC03 ไม่มีอะไรเลย ลอง input register:
```
> regs4 1 0 30
```

## ขั้นตอนที่ 2 — อ่าน 3 ตัวพร้อมกัน

เปิด `RS485_ReadAll/RS485_ReadAll.ino` แล้ว**แก้ตารางที่หัวไฟล์**ให้ตรงกับที่หาเจอ:

```c
static Sensor SENSORS[] = {
    { "O1 (oxygen)",   1, 3, 0, 1, DT_U16, 0.1f,  0.0f, "%"   },
    { "O2 (oxygen)",   2, 3, 0, 1, DT_U16, 0.1f,  0.0f, "%"   },
    { "PT (pressure)", 3, 3, 0, 1, DT_U16, 0.01f, 0.0f, "bar" },
};
//   ชื่อ            id  fc reg n  ชนิด    scale  offset หน่วย
```

`DT_*` เลือกตามที่ decode แล้วได้ค่าสมเหตุสมผล:
`DT_U16` · `DT_S16` · `DT_U32_ABCD` · `DT_U32_CDAB` · `DT_F32_ABCD` · **`DT_F32_CDAB`** (พบบ่อยสุดในของจีน)

อัปโหลด → Serial Monitor 115200 → จะเห็น:

```
[12]  O1 (oxygen) = 20.94 %   |   O2 (oxygen) = 20.87 %   |   PT (pressure) = 1.01 bar   |
      สถิติ:  O1 ok=12 err=0   O2 ok=12 err=0   PT ok=12 err=0
```

### สิ่งที่ต้องผ่าน

- **`err` ต้องเป็น 0** (หรือใกล้ 0 มาก)
- **O2 ต้องได้ ~20.9 %** ในอากาศปกติ — ถ้าได้เลขแปลก ๆ แปลว่า `scale` หรือ `DT_*` ยังผิด
- **O1 กับ O2 ต้องอ่านได้ใกล้เคียงกัน** (ถ้าห่างกันเยอะ = ตัวใดตัวหนึ่งต้องสอบเทียบ)

ถ้าตัวไหน FAIL มันจะบอกสาเหตุตรง ๆ (`ไม่ตอบ` / `CRC เพี้ยน` / `exc 2`) **ไม่แกล้งทำเป็นมีค่า**

### `err` ไต่ขึ้นเรื่อย ๆ = บัสไม่นิ่ง

| เช็ค | |
|---|---|
| **Terminator** | ต้องมี **120 Ω คร่อม A-B ที่ปลายบัสทั้ง 2 ข้าง** |
| **GND** | GND ของเซนเซอร์ทุกตัวต้องถึง GND ของ Nano |
| **A/B สลับ** | ลองสลับ A กับ B ดู |
| **สายยาว** | ใช้สายคู่บิดเกลียว (twisted pair) |

## เอาผลไปใส่โปรเจกต์หลัก

พอได้ค่าครบทั้ง 3 ตัวแล้ว มี 2 ทาง:

**ทางที่ 1 — ใส่ผ่านหน้าจอ (ไม่ต้องคอมไพล์ใหม่)**
แท็บ **SETUP → SENSORS** (PIN Expert `4444`) → ใส่ `slave / function / register / data type / scale` → **SAVE TO EEPROM**

**ทางที่ 2 — แก้ default ในโค้ด**
แก้ `settings_defaults()` ใน [`../settings.cpp`](../settings.cpp)

จากนั้น**เปลี่ยน `USE_DUMMY_SENSORS` เป็น `0`** ใน [`../Arduinonano_Display_O2_pressure.ino`](../Arduinonano_Display_O2_pressure.ino) แล้วอัปโหลดใหม่ → เครื่องจะใช้ค่าจากเซนเซอร์จริง

## คำสั่งทั้งหมดของ RS485_SetID

| คำสั่ง | ทำอะไร |
|---|---|
| `scan` | กวาดหา slave (ID 1-247) ที่ baud ปัจจุบัน |
| `scanall` | กวาดทุก baud (9600 / 4800 / 19200 / 38400) |
| `probe <id>` | หา register ที่เก็บ address ของตัวเอง |
| `regs <id> <start> <n>` | dump register (FC03) — มาร์กค่าที่ได้ ~20.9 ให้ |
| `regs4 <id> <start> <n>` | เหมือนบน แต่ใช้ FC04 (input register) |
| `read <id> <fc> <reg> <n>` | อ่านแบบเจาะจง + โชว์ byte ดิบ |
| `write <id> <reg> <val>` | เขียน register (FC06) — **ระวัง** |
| `setid <id> <reg> <new>` | ตั้ง ID ใหม่ + ยืนยันผล |
| `baud <b>` | เปลี่ยน baud ที่ใช้คุย |
| `help` | เมนู |

---

## หมายเหตุทางเทคนิค

เครื่องมือ 2 ตัวนี้ **ไม่ใช้ไลบรารี ModbusMaster** แต่เขียน Modbus RTU เอง เพราะ:

1. **ModbusMaster ล็อก response timeout ไว้ที่ 2000 ms** (`static const` เปลี่ยนตอน runtime ไม่ได้)
   → scan 247 ID จะกินเวลา **8 นาที** ต่อ baud เดียว
   เขียนเองทำให้ตั้ง timeout เป็น 80 ms ได้ → **scan เหลือ ~20 วินาที**
2. เห็น **byte ดิบ** ของทั้ง request และ response — จำเป็นมากตอนไล่ปัญหากับเซนเซอร์ที่ไม่มีคู่มือ
3. รองรับ **FC06 (write single register)** ที่ต้องใช้เขียน ID

โปรเจกต์หลักยังใช้ `ModbusMaster` ตามเดิม (ที่นั่นไม่ต้อง scan — รู้ ID แล้ว timeout 2 วินาทีจึงไม่เป็นปัญหา)

ขนาดโปรแกรม: `RS485_SetID` 47% flash / 28% RAM · `RS485_ReadAll` 24% / 28%
